# Описание транзакций

Предположительно, при описании сценария имелось в виду, что средства на счете клиента блокируются на время проверки платежа системой безопасности. Предполагается, что также будет существовать таймаут ручной проверки, который будет приводить к автоматическому подтверждению платежа. Кроме того, предполагается наличие возможности отмены платежа клиентом, контрагентом или же самой системой, из-за чего передача платежа будет иметь условную компенсацию, однако уже не без последствий, а потому в контексте Saga ее правильнее считать необратимой.

| Транзакция | Описание | Тип | Компенсация |
| --- | --- | --- | --- |
| CREATE_PAYMENT | Инициация платежа — валидация входных данных и начало процесса оплаты | компенсируемая | CANCEL_PAYMENT |
| RESERVE_FUNDS | Резервирование средств на счёте клиента | компенсируемая | RELEASE_RESERVED_FUNDS |
| FRAUD_CHECK | Проверка транзакции системой безопасности | повторяемая | - |
| PAYMENT_TRANSFER | Перевод средств контрагенту | необратимая | - |
| CANCEL_PAYMENT | Отмена платежа | повторяемая | - |
| MANUAL_REVIEW | Перевод на ручную проверку — ожидание решения в течение (20 мин) | повторяемая | - |
| RELEASE_RESERVED_FUNDS | Снятие резерва | повторяемая | - |
| REFUND_PAYMENT | Возврат средств клиенту | необратимая | - |
